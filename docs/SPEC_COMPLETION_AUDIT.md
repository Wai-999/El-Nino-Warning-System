# Approved-specification audit and repair loop

Audit started from `3c81616ea79af04a5b725ad9d9db6ebefab7fb42`; V3.2 follow-up, 1 November 2026. The owner authorized the master prompt, then explicitly made `ElNino_V3_Codex_Decisions.md` authoritative where choices conflict. This document supplements the 49-row [decision checklist](V3_DECISIONS_ACCEPTANCE.md); the [machine registry](../src/data/indicators.json) gives individual indicator contracts.

**Completion is not claimed for every literal capability.** The master’s definition of done permits an honestly unavailable capability with a specific reason. That acceptance rule does not turn an unavailable product into an implemented one. Human review, unvalidated scientific products and delivery infrastructure remain open below. V3.1’s earlier broad “implemented” labels were too generous about the full geographic hierarchy and some data requirements.

## Remaining gates and evidence needed

- **Source and rights:** official warning/bulletin machine feed with explicit geography, issue/validity, issuer taxonomy and redistribution terms; real station/catchment or verified flood-footprint evidence. MIMU’s separate TownPoint product requires prior written permission for web use, so it was not embedded. The explicitly licensed HDX boundary product and GeoNames extract have separate provenance.
- **Scientific engineering and validation:** long matched rainfall/water-balance/soil/vegetation distributions, product-specific method/calibration and Myanmar evaluation for standardized drought indices, calibrated local long outlooks and heatwave duration. These are unshipped work, not proof that upstream data never exists. External sources are linked; current numerical products are not invented.
- **Delivery infrastructure:** owner/provider credentials and a reviewed zero-cost subscriber/delivery architecture plus the missing verified warning feed. A saved-interest filter is not a functioning Telegram or browser-push subscription.
- **Human quality:** qualified Burmese critical-warning review, meteorological/agricultural/health source interpretation, assistive-technology sessions and physical low-end-phone testing. Automated checks cannot sign these off.

## Primary-source evidence (checked 1 November 2026)

- [Open-Meteo ECMWF definitions](https://open-meteo.com/en/docs/ecmwf-api): model resolution/interpolation, ensemble precipitation probability >0.1 mm in preceding hour, pressure units, wind direction, soil depths and derived variables. The actual 45-point request returned all 15 fields with 168 finite validated values each.
- [Open-Meteo pricing](https://open-meteo.com/en/pricing): 15 variables count fractionally as 1.5 requests per location; the expanded 45-point request costs about 67.5 weighted calls, about 270/day at four runs, plus at most 180/day for a bounded core-only fallback on every run. Existing daily baseline cap remains 4,500 and is never reset to bypass quota.
- [GeoNames extract/license/columns](https://download.geonames.org/export/dump/readme.txt), [feature codes](https://www.geonames.org/export/codes.html): CC BY 4.0, stable point IDs, separate feature classes, language-tagged names and record modification dates. Exact ZIP/geometry checksums are retained in `settlements.json`. A newer extraction date does not refresh an older source record or reference boundary.
- [ONI v6](https://www.cpc.ncep.noaa.gov/products/analysis_monitoring/enso/oni/v6/): explicitly versioned official table, provisional recent values; official monitoring now uses RONI. Original table’s last row omits both its closing row tag and unfilled trailing cells; the adapter and real fixture cover that case.
- [CPC SOI](https://www.cpc.ncep.noaa.gov/data/indices/soi) and [method FAQ](https://www.cpc.ncep.noaa.gov/data/indices/Readme.index.shtml): standardized block is distinct from pressure anomaly. FAQ has differing general/SOI baseline text, disclosed instead of asserting a harmonized baseline.
- [NOAA PSL MEI.v2](https://psl.noaa.gov/enso/mei/) and [raw data](https://psl.noaa.gov/enso/mei/data/meiv2.data): five-variable overlapping two-month index, missing sentinels and JRA55/JRA3Q transition. The app retains published values rather than recomputing the index.
